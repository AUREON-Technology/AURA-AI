## 3. How a turn actually retrieves (CODE-READ)

`AIKernel._gather_context` (`kernel.py:1037-1119`) runs, concurrently: `memory.recall` (3 hits, 80-token budget), `knowledge.retrieve(message, owner_id)` (`:1084` — **`KnowledgeEngine.retrieve`, not the strategy facade**), episodic history, goals, and the CAG prefix. `KnowledgeEngine.retrieve` (`engine.py:541-646`): embed query → Qdrant search (24 candidates, owner + global) ∥ BM25 over the owner's and the global shard (after a per-owner corpus-revision convergence, `:699-763`) → drop lexical hits whose document version is no longer active (`:765-795`) → RRF (`k=60`) → rerank (heuristic by default; a raised reranker degrades to heuristic scoring, `:824-867`) → threshold 0.35 on the reranker score → token-Jaccard MMR → top 2. `ContextEngine` then keeps at most 2 chunks and clips each to 280 characters (`context/engine.py:305-307`).

Properties that hold by construction and are worth preserving: content-hash idempotency and per-id/per-hash in-process locks on ingest (`engine.py:249-256, 270-281`); explicit `ConflictError` when a caller names someone else's document id (`:283-292`); a partially-embedded document is never recorded (`:431-440`); the score floor can return nothing and the API says so (`v3.py:845-847`); the missing-owner vector point matches no filter (`qdrant_store.py:401-404`); a different embedding model is a different physical index and `resolve_for_read` refuses a mismatch (`index_manager.py:159-179`).
