## Decisions made while implementing

- **Tool namespace is `bp<version>_<name>`, not `bp.<version>.<name>`.** `ToolSpec` only accepts
  `[a-z0-9_]`, and provider function names cap at 64 characters. `generated_tool_name()` is the one
  definition. The roadmap and ADR-024 are corrected to match.
- **"Fourteen kinds" is 13 element kinds plus the Provenance record.** Provenance is attached to
  every element; it is not an element itself. ADR-020 and the roadmap are corrected to match.
- **Twin digest excludes the version**, so re-discovering an unchanged system produces the same
  digest. That is the property AP4's diff relies on.

What the tests pin:

- `UntrustedText` never leaks through `str`, `format` or `repr`. It neutralises an injected fence
  terminator exactly as `ContextBundle.render` does, and that render output is unchanged after the
  refactor.
- Sanitising strips control and bidi-override characters, applies NFKC and caps the length.
  Decoding refuses such content instead of cleaning it.
- Provenance rules: an `llm*` extractor at confidence 1.0 is refused.
- AUSM shape rules per kind. A twin refuses unsorted or duplicate elements, dangling or mistyped
  references, and sources without a SOURCE element.
- Digests: stable under 25 randomised key orderings, and under input order and version for twins.
  They change with any content change.
- Strict decode names the failing path for unknown keys, missing keys, `true` given as an integer,
  bad enums, an injected `side_effecting`, control characters in untrusted text, non-finite
  numbers and the wrong schema version.
- Blueprint cross-references:
  - every agent tool resolves;
  - an agent's ceiling is at least each of its tools' sensitivity;
  - generated tools are never SYSTEM-sensitive;
  - generated and native tool names never clash;
  - view fields exist in the tool's `output_schema`;
  - navigation targets exist.
- `check_against_twin` refuses a blueprint compiled from a different twin, and AUSM references that
  are missing or of the wrong kind.
- Lifecycle: skipping evaluation or approval, leaving `rejected`, or acting on a stale digest raises
  `ConflictError`. Rollback (`superseded → active`) is allowed.
