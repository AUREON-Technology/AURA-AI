What exists: a keyset-paged list (`(created_at, id)`, `order`, `role`, cursors refused for another list), read one, edit and delete. The list and the read return the ciphertext and the plaintext metadata (`role`, `model_used`, `tokens_used`, `persona`, times). **An edit is the client's own new ciphertext** for text, citations or tool calls, accepted only in an envelope shape (`gcm2:` or `gcm:`, so plaintext cannot land in a `*_enc` column), the text cannot be cleared, the role cannot change, a deleted message is not edited back to life, and it re-stamps the row so the other devices pull it. **A delete is the sync's tombstone** with its ciphertext cleared (audit F-07); a retried delete is another 200. (3) **A stop-generation route**: the stream announces its run and turn ids only at its end, so a client has nothing to name before then; closing the connection stops a plain stream, and `POST /agents/runs/{id}/cancel` stops a run that already has an id, at its next step. Announcing the id in a first frame is a protocol change I did not make unasked. (4) **Create a message without a reply**: sending is `/chat`; a message row is created by the app's sync. (5) **Attachments**: `/chat` takes up to 8 images that are described and not kept; there is no upload or management, and the general file store waits for the owner's storage bucket. (6) **The server's working transcript** (what the model is shown next turn) has no message ids, so deleting or editing one message does not change it; `DELETE /sessions/{id}` forgets it.
